# BESPOKE summary

> Readable summary of [BESPOKE.md](BESPOKE.md), which stays the authoritative protocol. Every stage updates both files.

## What this project is

- A tailored fork of https://github.com/portainer/portainer, following tag 2.45.3 at upstream commit 0fa764dc81c76bb7914d65d8e62b026d7c746899.
- Vision: A single-user, locally reachable Portainer for Docker on the same machine, without user management, login, Kubernetes, Swarm, edge, registries, or backup/restore, plus a maintenance screen for unused containers and images, and no commercial-edition advertising.
- Constraints: Do not touch the core functionality for managing local Docker resources.

**3-tailored** (TAI-001 to TAI-021). The user confirmed the removals of login and user management (with a directly usable first start and no admin setup), Kubernetes, Docker Swarm, Edge, registries, backup/restore, the Portainer Agent and remote Docker hosts, Azure Container Instances, the host filesystem browser, the volume file browser, and the GitOps workflows view, and later commercial advertising with the Business Edition upsell, environment groups and tags, and the container webhook UI. The decisions are recorded. Login and user management are removed (TAI-001): there is no sign-in, no users, teams, roles, ownership or access tokens, first start opens directly, and the local API needs no login; theme preferences stay. Kubernetes is removed (TAI-002): no Kubernetes environments, dashboard, kubectl shell, kubeconfig, Helm or Kubernetes settings; code that Edge still reaches stays until TAI-004. Docker Swarm is removed (TAI-003): no Swarm environments, cluster or node views, visualizer, services, tasks, configs, secrets or service webhooks; a Swarm member engine is shown as a standalone engine, and old Swarm stack records can only be viewed and deleted. Edge computing is removed (TAI-004): no Edge Agents or tunnel, no Edge groups, stacks, jobs or templates, no Edge settings, onboarding script or update schedules, and no KubeSolo Edge option; custom templates are Compose only, and old Edge environment records can only be removed. Registries are removed (TAI-005): no registry catalog, per-environment registry access, Docker Hub pull-limit check or push to a registry; images are pulled, tagged and committed by their full name, which can carry a registry host. Backup and restore are removed (TAI-006): no "Back up Portainer" download, no restore from a file and no scheduled backups; the database keeps its own backup before migrations. The Portainer Agent and remote Docker hosts are removed (TAI-007): environments connect only through the local Docker or Podman socket, there is no per-node targeting, no Agent version filter and no PCI devices, disks or disk usage on the host page; a stack can be renamed or duplicated but no longer migrated to another environment, and old Agent environment records can only be removed. Azure Container Instances are removed (TAI-008): no ACI environments, Azure dashboard or container instance views, and old Azure environment records open their details page and can only be edited and removed; Git repositories on Azure DevOps still work. The host filesystem browser is removed (TAI-009): the host page shows host and engine details without a Browse button, and the host management features toggle is gone. The volume file browser is removed (TAI-010): volumes are listed, created, inspected and removed as before but their files can no longer be browsed, and every browse request is refused. The GitOps workflows view is removed (TAI-011): there is no Workflows page or API; Git sources still show the workflows that use them, each linking to its stack, and stack Git deploy is unchanged. Commercial advertising and the Business Edition upsell are removed (TAI-012): no "Upgrade to Business Edition" banner, no Portainer news on the home screen, no Activity logs teaser, no "Get Help" link to commercial support and no disabled Business Edition switches in settings, the Docker features configuration, Git automatic updates or editor stacks; the version check and the credits stay. Environment groups and tags are removed (TAI-013): no Groups or Tags pages, no group or tag fields when adding or editing an environment, no group column or Group sort, and no tags on the dashboard; every new environment joins the Unassigned group, and the database keeps old groups and tags unchanged. The container webhook UI is removed (TAI-014): no "Create a container webhook" switch and no webhook row in the container details, a Business Edition teaser whose API had been gone since TAI-003; duplicating or editing a container opens its prefilled form again, and stack webhooks are unchanged. The dead code these removals left behind is being removed without a visible change (TAI-015 to TAI-019). New instances always start fresh, so the database loses its dead collections (TAI-020) and the always-empty ones with the code that still read them (TAI-021).
